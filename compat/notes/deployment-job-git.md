# ApplicationDeploymentJob: git-based applications from a public repository (exact behaviour spec)

Source: Coolify main @ b5823c7, `.upstream/snapshot`. All `file:line` references are relative to the snapshot.
Abbreviations: **ADJ** = `app/Jobs/ApplicationDeploymentJob.php`, **ERC** = `app/Traits/ExecuteRemoteCommand.php`,
**APP** = `app/Models/Application.php`, **AC** = `app/Http/Controllers/Api/ApplicationsController.php`.

This document covers **only what differs** from the Docker-image path. Everything not mentioned here (command runner,
log entry format, redaction, helper container start, labels, runtime `.env`, rolling update, health check loop,
`post_deployment`, `finally`, `failed()`) is exactly as in `compat/notes/deployment-job-dockerimage.md` (**DIS**), and
the shared API create prologue is as in `compat/notes/applications-api.md` (**AAS**) section 2.1.

Scope: `pull_request_id = 0`, no build server, no additional servers, standalone Docker (not Swarm), root SSH user,
`isDev() = false`, no webhooks, no previews.

Extra placeholders (in addition to DIS's `{dep}`, `{U}`, `{net}`, `{cn}`, `{workdir}`, `{basedir}`, `{cfg}`, `{helper}`, `{T}`):

| Placeholder | Value |
|---|---|
| `{repo}` | `$this->customRepository` = `customRepository()['repository']` (section 2.2). Public GitHub: `owner/repo`; other hosts: the stored full URL |
| `{branch}` | `applications.git_branch` |
| `{sha}` | the job commit after resolution (40-hex SHA, or the literal `HEAD` when unresolved) |
| `{repoUrl}` | `$this->fullRepoUrl`: public GitHub `https://github.com/{repo}` (= `source.html_url.'/'.{repo}`, **no `.git` appended**); other hosts: the stored URL |
| `{img}` | production image name (section 2.6), e.g. `{U}:{sha}` |
| `{bimg}` | build image name, e.g. `{U}:{sha}-build` |
| `{df}` | `$this->dockerfile_location` (default `/Dockerfile`) |
| `{ex(x)}` | `executeInDocker({dep}, x)` = `docker exec {dep} bash -c '` + x with every `'` replaced by `'\''` + `'` (docker.php:543) |
| `{q(x)}` | `escapeshellarg(x)` / `escapeShellValue(x)` = `'` + x with `'`→`'\''` + `'` |

   `install_command/build_command/start_command` = `shellSafeCommandRules()` (`nullable|string|max:1000|regex:SHELL_SAFE_COMMAND_PATTERN`,

2. **`Validator::make($request->all(), $rules, ['docker_compose_domains.*.array' => 'An item in the docker_compose_domains array has invalid fields. Only name, domain, and redirect fields are supported.'])`**
   — not `customApiValidator`, so the `required` message is Laravel's default (`The git repository field is required.`,
   `The build pack field is required.`), enum → `The selected build pack is invalid.`. Fail → `422 {"message":"Validation failed.","errors":{field:[msgs]}}`.
   Error key order follows the merged rule order (wildcard rules expand in place).
   - `ValidGitRepositoryUrl` (app/Rules/ValidGitRepositoryUrl.php), first failure wins, `:attribute` = `git repository`:
     empty → pass; on `rawurldecode(value with a bracketed IPv6 host replaced by ipv6-host)`: control chars `[\x00-\x1F\x7F]` → `The :attribute contains invalid characters.`;
     any of `; | & $ \` ( ) { } [ ] < > \n \r \0 " ' \ ! ? * ^ % = + #` (note `'\n'`, `'\r'`, `'\0'` are the literal 2-char strings in single quotes) → same message;
     patterns `\$\(.*\)`, `\${.*}`, `;;`, `&&`, `\|\|`, `>>`, `<<`, `\\\n`, `\.\.[\/\\]` → `The :attribute contains invalid patterns.`;
     then by form (on the undecoded value): scp `user@host:` → `parseScpStyleGitUrl` + host/path regexes else `The :attribute is not a valid SSH repository URL.`;
     `ssh://` → `/^ssh:\/\/[a-zA-Z0-9._-]+@(\[[0-9A-Fa-f:.]+\]|[a-zA-Z0-9.-]+)(:[0-9]{1,5})?\/[a-zA-Z0-9\-_\/.~%]+$/` else same;
     `http(s)://` → `FILTER_VALIDATE_URL` else `The :attribute is not a valid URL.`; host in `localhost,127.0.0.1,0.0.0.0,::1`, reserved IP, or `*.local` → `The :attribute cannot point to internal hosts.`;
     `%` in host/user/pass → invalid characters; query/fragment → `The :attribute should not contain query parameters or fragments.`;
     path not `/^[a-zA-Z0-9\-_\/\.@~%]+$/` → `The :attribute path contains invalid characters.`;
     `git://` regex else `The :attribute is not a valid git:// URL.`; else `The :attribute must start with https://, http://, git://, ssh://, or be an SSH URL (user@host:path).`
   - `ValidGitBranch` (app/Rules/ValidGitBranch.php) on `trim(value)`: chars `; | & $ \` ( ) { } < > \n \r \0 " ' \ ! * ? [ ] ~ ^ : space #` → `The :attribute contains invalid characters.`;
     `..`, `//`, `@{` → `... contains invalid patterns.`; starts/ends with `/` or `.` → `The :attribute cannot start or end with / or .`;
     not `/^[a-zA-Z0-9\-_\/\.]+$/` → `The :attribute contains invalid characters. Only letters, numbers, hyphens, underscores, forward slashes, and dots are allowed.`;
     `HEAD` → `The :attribute cannot be HEAD.`; `.lock` suffix → `The :attribute cannot end with .lock.`

### 1.3 Stored defaults for a minimal request
`{"project_uuid","environment_name","server_uuid","git_repository":"https://github.com/coollabsio/coolify-examples","git_branch":"main","build_pack":"nixpacks","ports_exposes":"3000"}` →
`git_repository='coollabsio/coolify-examples'`, `git_branch='main'`, `git_commit_sha='HEAD'` (DB default), `source_type='App\Models\GithubApp'`, `source_id=0`,
`private_key_id=null`, `base_directory='/'` (DB default; setter only runs if sent), `publish_directory=null`, `dockerfile_location=null`,
`docker_compose_location='/docker-compose.yaml'`, `static_image='nginx:alpine'`, `install/build/start_command=null`, `ports_exposes='3000'`,
fqdn autogenerated, `custom_labels` generated, settings defaults (AAS 2.5: `is_git_submodules_enabled=true`, `is_git_lfs_enabled=true`,
`is_git_shallow_clone_enabled=true`, `inject_build_args_to_dockerfile=true`, `include_source_commit_in_build=false`, `use_build_secrets=false`,

Write sequence (non-static, nixpacks): INSERT app → INSERT settings → UPDATE app compose_parsing_version → INSERT env var + INSERT preview env var →
[UPDATE settings per sent field] → [UPDATE app fqdn] → UPDATE app custom_labels → UPDATE app config_hash.

### 1.4 `build_pack = dockercompose` at creation: `Application::loadComposeFile($isInit = false)` (APP:2356-2436)
Runs from the queued `LoadComposeFile` job (only when not instant-deploying) **and again at every deployment** (section 3d). Runs **on the
application's destination server host via `instant_remote_process`, not in a helper container**, without deployment logs.
1. `$isInit && docker_compose_raw` → return (not the API case).
2. `$uuid = new_public_id()`; `getGitRemoteStatus($uuid)` (APP:1617): `generateGitLsRemoteCommands(exec_in_docker: false)` (APP:1635) → public GitHub:
   `instant_remote_process(["git ls-remote 'https://github.com/{repo}'"])` (no ref, lists all refs; 'other': `git ls-remote '{url}'`). A `RuntimeException` →
   `RuntimeException('Failed to read Git source. Please verify repository access and try again.'.gitFailureReason(...))` where `gitFailureReason` (APP:2241) masks `scheme://user@` as `scheme://***@`, logs to laravel.log, and returns `'<br><br>Reason: '.e(last non-empty stderr line, limit 300)` or `''`.
3. `composeFileReadCommands($uuid)` (APP:2288), one `instant_remote_process` (lines joined by `\n`):
   ```
   rm -rf /tmp/{uuid}
   mkdir -p /tmp/{uuid}
   cd /tmp/{uuid}
   sh -c '<clone>'
   cd /tmp/{uuid}/checkout
   git read-tree HEAD                       # only if is_git_submodules_enabled (default true)
   sh -c '<submodule loop>'                 # only if is_git_submodules_enabled
   sh -c '<read compose file>'
   ```
   - `<clone>` = `generateGitImportCommands(only_checkout: true, exec_in_docker: false, custom_base_dir: '/tmp/{uuid}/checkout')` with `' clone '` → `' clone --quiet '`:
     public GitHub default settings: `git clone --quiet --depth=1 --recurse-submodules --shallow-submodules --no-checkout -b '{branch}' 'https://github.com/{repo}' '/tmp/{uuid}/checkout'`
     (no commit checkout, no submodule/LFS step: only-checkout skips `setGitImportSettings`).
   - `{file}` = `ltrim(rtrim(base_directory,'/').docker_compose_location, '/')`, e.g. `docker-compose.yaml`.
   - `<submodule loop>` = `git ls-files -s | while read -r mode object stage path; do if [ "$mode" = 160000 ]; then case '{file}' in "$path"/*) git submodule update --init --recursive --depth=1 -- "$path" >/dev/null || exit 1 ;; esac; fi; done` (`--depth=1` only with shallow clone).
   - `<read compose file>` = `file='{file}'; [enter-submodule loop] git ls-tree HEAD -- "$file" | { read -r mode type object path; case "$mode" in 100644|100755) ;; 120000) echo 'The Docker Compose file is a symbolic link.' >&2; exit 1 ;; *) echo 'No such file' >&2; exit 1 ;; esac; if [ "$(git cat-file -s "$object")" -gt 5242880 ]; then echo '__COOLIFY_COMPOSE_TOO_LARGE__'; else git cat-file blob "$object"; fi; }`
     where the enter-submodule loop (only with submodules) is `while sub=$(git ls-tree -r HEAD | while read -r mode type object path; do if [ "$mode" = 160000 ]; then case "$file" in "$path"/*) echo "$path"; break ;; esac; fi; done) && [ -n "$sub" ]; do cd "$sub" || exit 1; file="${file#"$sub"/}"; done;`
   - So the file is read from the **branch tip** (`-b {branch}`), never from `git_commit_sha` or the deployment commit.
4. Output is `trim()`med by `instant_remote_process` (so leading/trailing whitespace of the file is lost). `__COOLIFY_COMPOSE_TOO_LARGE__` or > 5 MiB → `Docker Compose file exceeds the 5 MiB size limit.`
   Errors (each restores and saves `docker_compose_location`/`base_directory`): symlink → `Docker Compose file at {workdir}{loc} (branch: {branch}) is a symbolic link. Coolify reads only regular files from the repository. Commit the file itself instead of a link to it.`;
   `No such file` → `Docker Compose file not found at: {workdir}{loc} (branch: {branch})<br><br>Check if you used the right extension (.yaml or .yml) in the compose file name.`;
   `fatal: repository … does not exist` → `Repository does not exist. Please check your repository URL and try again.`; else `Failed to read the Docker Compose file from the repository.{reason}`.
   `finally`: `instant_remote_process(["rm -rf /tmp/{uuid}"], throwError: false)`.
5. `validateDockerComposeForInjection($content)` (parsers.php:44) failure → restore+save, `DeploymentException(e("The Docker Compose file at {workdir}{loc} (branch: {branch}) is not safe to use, so Coolify did not load it. {msg}"))` (HTML-escaped).
6. `docker_compose_raw = content`; save; `parse()` (APP:2225 → `applicationParser($this, 0, null, null)`, section 3d; persists `docker_compose`, env vars, volumes, domains); if `docker_compose_domains` set → `reconcileDockerComposeDomains` (re-key to service names, drop unknown; save).
7. Empty content → restore+save, `RuntimeException("Docker Compose file not found at: …")`.
In the API job context failures only reach the failed-jobs table / laravel.log.

## 2. Deployment: what changes for git apps

### 2.1 Constructor / `handle()` differences
- `queue_application_deployment` (applications.php:21) sets `commit = $commit ?: (git_commit_sha ?: 'HEAD')`; the constructor `validateGitRef`s it (DIS 2).
- `restart_only` stays true only for `nixpacks`, `static`, `railpack` (ADJ:263); a restart of `dockerfile`/`dockercompose` is a full deployment (which skips the build when the image exists).
- `$this->source` = the GithubApp row (public GitHub) or `'other'`.
- `handle()` (ADJ:394-410), unchanged commands, but now **used**:
  - `addHosts` (ADJ:328-356): `.Containers` of `docker network inspect '{net}'` sorted (PHP `sort` on the container maps ⇒ effectively by `Name`),
    skip `coolify-proxy`, names matching `-\d{8}T\d{6}$` / `-\d{12}$`, and names that are any `application_deployment_queues.deployment_uuid`;
    `--add-host {Name}:{IPv4 before /}` joined by single spaces (`''` when none; `null` if inspect printed `null`). Inserted into every `docker build`/`buildx build`.
  - `buildTarget` = `" --target {dockerfile_target_build} "` (leading and trailing space) when set, after `DOCKER_TARGET_PATTERN` check
    (`RuntimeException('Invalid dockerfile_target_build: contains forbidden characters.')`); else `null`.
  - `['repository' => customRepository, 'port' => customPort] = $application->customRepository()`.
- `selectBuildServer()` (ADJ:461): git build packs are not exempt from "deployment-only server must build elsewhere" (out of scope; with a buildable server and `is_build_server_enabled=false` it returns silently).
- `detectBuildKitCapabilities()` results now matter: `dockerBuildkitSupported`, `dockerBuildxAvailable`, `dockerSecretsSupported` (only if `settings.use_build_secrets`).

### 2.2 `customRepository()` (APP:1553) → `convertGitUrl(git_repository, deploymentType(), source)` (shared.php:4926)
- `deploymentType()` (APP:1421): `private_key_id > 0` → `deploy_key`; source set → `source`; `private_key_id === 0` → `deploy_key`; else `other`.
- Public GitHub (`source`, repo `owner/repo`): no `://`, no scp match → `['repository' => 'owner/repo', 'port' => 22]`.
- `other` with `https://host[:port]/path`: `repository` = the URL unchanged, `port` = `(string)` URL port if present, else `22`.
- Public repos are **always HTTPS** (`https://github.com/{repo}` or the stored http(s)/git URL); SSH is only used for `deploy_key` sources.
  The `GIT_SSH_COMMAND` prefixes below are still emitted but have no effect on HTTPS.

### 2.5 Clone: `clone_repository()` (ADJ:3487) → `import_repository()` (ADJ:3517) → `Application::generateGitImportCommands()` (APP:1845) + `setGitImportSettings()` (APP:1568)
1. log `"\n----------------------------------------"` (stored trimmed: `----------------------------------------`).
2. log `Importing {repo}:{branch} (commit sha {sha}) to {basedir}.` — e.g. `Importing coollabsio/coolify-examples:main (commit sha 3f2a…) to /artifacts/{dep}.`
3. `import_repository()`: loop `attempt = 1..`:
   - `execute_remote_command(...gitCommandDefinitions(generate_git_import_commands()))`. For public GitHub and `other` the generator returns **one string**
     (`gitCommandsAsShellCommand` joins with ` && `), so `gitCommandDefinitions` (ADJ:3555) yields exactly one `[cmd, 'hidden' => true]`.
   - `DeploymentException` with code `255` and `attempt < config('constants.ssh.max_retries')` (3): log (stderr, visible)
     `Lost the SSH connection while importing the repository. Retrying in {d}s (attempt {attempt+1}/{max}).` with `d = min(2 * 2^(attempt-1), 30)`,
     sleep `d`, then `execute_remote_command([{ex(pkill git; rm -rf {q({basedir})})}, hidden, ignore_errors])` and retry. Any other code (git uses 128) rethrows.
   - (ERC's own SSH retry loop runs first inside each attempt, DIS 1.1.)
4. `create_workdir()` (DIS 5.4 step 2: `{ex(mkdir -p {workdir})}` then `mkdir -p {cfg}` on the host; not hidden, no output).
5. `execute_remote_command([{ex(cd {workdir} && git log -1 {q({sha})} --pretty=%B)}, hidden, save 'commit_message'])` (`{sha}` may be `HEAD`).
   If non-empty: `queue.commit_message = trim(saved)` in memory (not saved itself) and
   `UPDATE application_deployment_queues SET commit_message = ? WHERE commit = {sha} AND application_id = {app}` (all rows with that commit, incl. this one; Eloquent builder adds `updated_at`).

**The clone command** (public GitHub; `other` is identical with `{repoUrl}` = stored URL):
```
git clone{depth}{subm} -b {q(branch)} {q(repoUrl)} {q(basedir)}{commitPart}{submodulePart}{lfsPart}
```
- `{depth}` = ` --depth=1` if `is_git_shallow_clone_enabled` (default true) else `''`.
- `{subm}` = ` --recurse-submodules` if `is_git_submodules_enabled` (default true), plus ` --shallow-submodules` when shallow; else `''`.
- `{ssh}` = `GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null"` (default in `setGitImportSettings` because the public/other path passes no ssh command).
- `{commitPart}` — commit used = the job commit (`$commit ?? git_commit_sha`); only if `!== 'HEAD'`:
  - shallow: ` && cd {q(basedir)} && echo 'Fetching the commit.' && {ssh} git fetch --depth=1 origin {q(sha)} && git -c advice.detachedHead=false checkout {q(sha)} >/dev/null 2>&1`
  - not shallow: ` && cd {q(basedir)} && {ssh} git -c advice.detachedHead=false checkout {q(sha)} >/dev/null 2>&1`
- `{submodulePart}` (submodules enabled): ` && cd {q(basedir)} && if [ -f .gitmodules ]; then sed -i "s#[A-Za-z0-9._-]*@\(.*\):#https://\1/#g" {q(basedir)}/.gitmodules || true && echo 'Updating submodules.' && git submodule sync && {ssh} git submodule update --init --recursive {sflag}; fi`
  with `{sflag}` = `--depth=1` when shallow else `''` (giving `--recursive ; fi`). The `sed` rewrite is only emitted for public/other (`public: true`).
- `{lfsPart}` (LFS enabled): ` && cd {q(basedir)} && if git lfs ls-files -n | grep -q .; then echo 'Downloading Git LFS objects.' && {ssh} git lfs pull; fi`
- The whole string goes through `{ex(...)}`. Default rendering (`{dep}` = `abc`, repo `o/r`, branch `main`, resolved `{sha}`):
  ```
  docker exec abc bash -c 'git clone --depth=1 --recurse-submodules --shallow-submodules -b '\''main'\'' '\''https://github.com/o/r'\'' '\''/artifacts/abc'\'' && cd '\''/artifacts/abc'\'' && echo '\''Fetching the commit.'\'' && GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null" git fetch --depth=1 origin '\''{sha}'\'' && git -c advice.detachedHead=false checkout '\''{sha}'\'' >/dev/null 2>&1 && cd '\''/artifacts/abc'\'' && if [ -f .gitmodules ]; then sed -i "s#[A-Za-z0-9._-]*@\(.*\):#https://\1/#g" '\''/artifacts/abc'\''/.gitmodules || true && echo '\''Updating submodules.'\'' && git submodule sync && GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null" git submodule update --init --recursive --depth=1; fi && cd '\''/artifacts/abc'\'' && if git lfs ls-files -n | grep -q .; then echo '\''Downloading Git LFS objects.'\'' && GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null" git lfs pull; fi'
  ```
- Log output (all hidden, batch = this call): git's `Cloning into '/artifacts/abc'...` (stderr), `Fetching the commit.` (stdout), fetch progress / `From https://github.com/o/r` + ` * branch {sha} -> FETCH_HEAD` (stderr), `Updating submodules.` / `Downloading Git LFS objects.` only when applicable.
- Always clones into `{basedir}` (`/artifacts/{dep}`), regardless of `base_directory`.

### 2.9 `set_coolify_variables()` (ADJ:3258) — `{coolvars}`

## 4. `generate_compose_file()` and rolling update differences for built images

### 4.1 Compose content (ADJ:4364-4606)
Identical structure to DIS 5.4 with:
- `image: {img}` = `{U}:{sha}` (or `{registry}:{sha}`); the static/nginx variants also tag `{img}`.
- `expose`, `PORT`, healthcheck port: `main_port()` = `[80]` if `settings.is_static`, else `ports_exposes` split.
- Labels: same rules (stored `custom_labels` normally generated at creation).
- File is written to the workdir only in `rolling_update()` after the build (so it is not in the build context).

### 4.2 Dockerfile HEALTHCHECK (`build_pack === 'dockerfile'` or inline Dockerfile)
Inside `generate_compose_file()` after the labels (ADJ:4398-4406):
`execute_remote_command([{ex(cat {workdir}{df})}, hidden, save 'dockerfile_from_repo', ignore_errors])` (the whole Dockerfile is logged as hidden stdout; a missing file logs/saves cat's stderr), then
`application->parseHealthcheckFromDockerfile(saved)` (APP:2715):
- lines = `trim(content)` split `\n`; `hasHealthcheck` = the JSON of that collection contains `HEALTHCHECK` (anywhere, comments included).
- no HEALTHCHECK but `custom_healthcheck_found` → reset `custom_healthcheck_found=false, health_check_interval=5, timeout=5, retries=10, start_period=5`, save.
- HEALTHCHECK and health check **disabled** (`health_check_enabled === false`, the default): first line starting with `HEALTHCHECK` (trimmed of `\` and spaces) plus continuation lines up to the first line without `\`;
  `--interval=`, `--timeout=`, `--start-period=` (`[0-9]+[a-zµ]*`) → `parseDockerfileInterval` (shared.php:4998: digits × unit `ns/us/µs/ms/s/m/h`, default s, int) into `health_check_*`; `--retries=(\d+)` → int.
  Then (Stringable objects are always truthy) **any non-empty HEALTHCHECK line** sets `custom_healthcheck_found = true` and saves (even `HEALTHCHECK NONE`).
- Effect: the compose has no `healthcheck` key (disabled), so the image's own HEALTHCHECK applies; `health_check()` logs `Using the custom healthcheck from the Dockerfile.` and polls `.State.Health.Status` (DIS 5.6) with the parsed retries/interval/start period instead of returning immediately.
- With Coolify's health check enabled, nothing is parsed and the generated `healthcheck` overrides the image's.

### 4.3 Rolling update / start differences
- `start_by_compose_file()` (ADJ:5269) for non-dockerimage: no `Pulling latest images from the registry.` log and no `pull`; one command
  `[{ex({coolvars} docker compose --project-name {U} --project-directory {workdir} -f {workdir}/docker-compose.yaml up --build -d)}, hidden]`

- `write_deployment_configurations()` with preserve-repository: `mkdir -p {cfg}` + `docker cp {dep}:{workdir}/. {cfg}` copies the build context (repo) to the host.

### 5.1 `generate_buildtime_environment_variables()` (ADJ:2202-2450)
Ordered map `KEY => escaped value` (later writes replace the value but keep the key's first position), converted to `KEY=value` lines; every key passes
`validatedBuildtimeEnvironmentVariableKey` (`ENVIRONMENT_VARIABLE_KEY_PATTERN` `/\A[A-Za-z_][A-Za-z0-9_.]*\z/u`, else the invalid-name log block ADJ:2634 + already-logged `DeploymentException`).
1. nixpacks only: plan `variables` (skipping `COOLIFY_*`/`SERVICE_*`) → `escapeBashEnvValue(value)`.
2. `generate_coolify_env_variables(forBuildTime: true)` (ADJ:4245-4292), pr 0, each → `escapeBashEnvValue` (null → `''`):
   - `SOURCE_COMMIT = commit` only if `include_source_commit_in_build` and no user var `SOURCE_COMMIT`.
   - parsing ≥ 3: `COOLIFY_URL = fqdn` (raw, may be null) unless user defines **`COOLIFY_FQDN`**; `COOLIFY_FQDN = hostsFromFqdn(fqdn)` unless user defines **`COOLIFY_URL`** (crossed guards).
   - non-dockercompose (or parsing 1/2): `COOLIFY_BRANCH = $this->branch` (= git_branch) and `COOLIFY_RESOURCE_UUID = {U}` unless user-defined. No `COOLIFY_CONTAINER_NAME`, no `COOLIFY_APP_NAME/PROJECT_NAME/ENVIRONMENT_NAME/SERVER_IP` at build time.
   ("User defines" = any non-preview env var of the app with that key, build-time or not.)
3. dockercompose: `SERVICE_NAME_{SVC}` (from the parsed `docker_compose`, `-`/`.` → `_`, upper) then `SERVICE_URL_{SVC}` / `SERVICE_FQDN_{SVC}` from `docker_compose_domains` (first URL, port removed), all `escapeBashEnvValue`.
4. User vars: `environment_variables()->withoutBuildpackControlVariables()` (key `NOT LIKE 'NIXPACKS_%'` and `NOT LIKE 'RAILPACK_%'`) `->where('is_buildtime', true)->orderBy(is_env_sorting_enabled ? 'key' : 'id')`, minus legacy invalid keys; dockercompose also drops `SERVICE_FQDN_/URL_/NAME_*` and compose-null-unset vars; railpack drops Docker-client keys.
   - remote-secret reference → `escapeBashEnvValue(resolved raw)`.
   - `is_literal || is_multiline` → `escapeBashEnvValue(trim(getResolvedValueWithServer(mainServer), "'"))`.
   - else → `escapeBashDoubleQuoted(resolved)` (docker.php:2079): `\`→`\\`, `"`→`\"`, `` ` ``→`` \` ``, `$` not followed by `[a-zA-Z_0-9{]` → `\$`, then `\\` before `$` → `\`; wrapped in `"…"`; empty/null → `""`. So `$VAR`/`${VAR}` expand when sourced (e.g. `APP_URL=$COOLIFY_URL`).
- `escapeBashEnvValue` (docker.php:2044): null/`''` → `''`; else `'` + (`'` → `'\''`) + `'`.
