coolify-rs 4.7.5-rs.1 matches **Coolify 4.7.5**, the current Coolify release. If your Coolify updates itself, this is the release that can take it over.

coolify-rs is an independent reimplementation of Coolify in one Rust service. It is not affiliated with or endorsed by coolLabs.

## Install

On a clean server, as root:

```bash
curl -fsSL https://github.com/coolify-rs/coolify-rs/releases/latest/download/install.sh | sudo bash
```

Requirements, settings and upgrades: [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md).

## Migrate from Coolify 4.7.5

Back up, run the dry-run check, then run the same installer on your Coolify server. It keeps your database, secrets, SSH keys, proxy and running resources, and you can go back to Coolify 4.7.5 the same way: [docs/MIGRATING.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/MIGRATING.md).

On Coolify 4.6.0 or older: upgrade Coolify to 4.7.5 first, then migrate.

## Upgrade from 4.6.0-rs.1 to 4.6.0-rs.5

Use the Upgrade button, or `upgrade.sh` as in [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md#upgrade). On its first start, 4.7.5-rs.1 applies Coolify 4.7's 27 schema changes to your database, as Coolify's own upgrade would. From then on only Coolify 4.7.5 can take the database back.

## Breaking changes (from Coolify 4.7)

- **Older queued webhook deployments are cancelled** when a newer push arrives, per application, pull request and server, so only the latest commit is built. Turn it off in the application's Advanced settings, or with `is_auto_cancel_queued_deployments_enabled` in the API. Manual, API, restart and rollback deployments are never cancelled. `cancel_previous` (`none`, `queued` or `building`) on `/api/v1/deploy` does the same for API deployments.
- **The cloud provider token API** is limited to team admins and owners; other members get `403`.
- **The Resend sender** moved to the new `resend_from_address` and `resend_from_name` fields. API clients must use them; the upgrade copies the current values.

## What's new

Everything Coolify changed from 4.6.0 to 4.7.5, including:

- **Image vulnerability scanning.** Turn it on per server: Coolify scans the images of your resources, shows a security status per resource, can block a deployment, suggests fixed versions and switches to them, scans the host's OS packages, and sends alerts and a digest. Off by default.
- **SFTP, FTPS and WebDAV backup storages** next to S3, with a saved SFTP host key and an option to skip TLS verification for S3.
- **SSH host keys** of servers are saved on first connection, and a changed key is refused until you accept it on the server's Security page. coolify-rs keeps refusing by default, as before; Coolify's default only warns (`SSH_HOST_KEY_CHECKING=warn`). Ed25519 is the default for new keys, RSA keys get 4096 bits, and a private key can be rotated on all its servers in one step.
- **Named SMTP servers** with provider presets, a separate notification sender, and the Resend sender.
- **GitHub Deployments**: a GitHub App can show deployment status on GitHub.
- **Forgejo and Codeberg** in the Gitea App source, and Gitea App endpoints in the API.
- **Valkey** as an image of the Redis database type, and the default for new Redis databases; newer default images for the other databases.
- **Stars** for servers and resources, shown on the dashboard.
- **Scheduled tasks** can run without a shell, and tasks that keep failing are disabled; repeated failure notifications are sent at most once a day.
- **A Security page per server** with host key, terminal access, patching and vulnerabilities; maintenance mode has its own page.
- **Many fixes** to deployments, Docker Compose, environment variables, previews, backups, DNS records, logs and the proxy, and upstream's security hardening.

Also in this release:

- **Security hardening** across sign-in, password resets, uploads and outgoing requests. Details will be published once instances have had time to upgrade.

## Not yet run against real infrastructure

These were ported from Coolify's code and covered by tests, but not run against a real registry, storage or provider for this release: image scanning, SFTP/FTPS/WebDAV storages, private key rotation, GitHub Deployments, and named SMTP servers. Report problems in the issue tracker.

## Known differences

Read [docs/KNOWN_LIMITATIONS.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/KNOWN_LIMITATIONS.md) before you switch. Notable ones: coolify-rs has no MCP server; it has no realtime channel to the browser, so the vulnerability pages poll for progress; scan locks and progress live in memory, so a restart forgets them; sessions are held in memory, so restarts and upgrades sign everyone out.
