coolify-rs 4.6.0-rs.5 matches **Coolify 4.6.0**. It is a security hardening release. Upgrading is recommended for every instance.

coolify-rs is an independent reimplementation of Coolify in one Rust service. It is not affiliated with or endorsed by coolLabs.

## Upgrade from 4.6.0-rs.1 to 4.6.0-rs.4

Use the Upgrade button, or `upgrade.sh` as in [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md#upgrade). There are no database changes.

## Changed

- **Security hardening** across validation, sessions, outgoing requests and the plugin runtime. Details will be published once instances have had time to upgrade.
- **Client addresses behind the proxy.** The upgrade sets `COOLIFY_RS_TRUSTED_PROXIES` to the `coolify` Docker network when it is not set, so rate limits, the API allowlist and audit logs see each visitor's address instead of the proxy's. A value you set yourself is kept.
- **Secure cookies over HTTPS.** Cookies are marked `Secure` on requests that reach the proxy over HTTPS, without setting `COOLIFY_RS_SECURE_COOKIES`. Plain-http access on the server's IP keeps working.

## Install or migrate

On a clean server, or on a Coolify 4.6.0 server, as root:

```bash
curl -fsSL https://github.com/coolify-rs/coolify-rs/releases/latest/download/install.sh | sudo bash
```

See [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md) and [docs/MIGRATING.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/MIGRATING.md). Read [docs/KNOWN_LIMITATIONS.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/KNOWN_LIMITATIONS.md) before you switch.
