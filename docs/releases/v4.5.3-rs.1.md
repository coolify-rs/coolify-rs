The first release of coolify-rs: Coolify's behaviour in one Rust service that idles in about 30 MB and answers the API 6–9× faster.

coolify-rs serves Coolify's REST API, reads and writes Coolify's PostgreSQL database, encrypts secrets the same way, runs the same commands on your servers and shows the same interface. It is an independent project, not affiliated with or endorsed by coolLabs.

This release matches **Coolify 4.5.3**.

## Install

On a clean server, as root:

```bash
curl -fsSL https://github.com/coolify-rs/coolify-rs/releases/latest/download/install.sh | sudo bash
```

Then open `http://<your-server>:8000` and register. Requirements, settings and upgrades: [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md).

## Migrate from Coolify 4.5.3

Back up, check, then run the same installer on your Coolify server. It keeps your database, secrets, SSH keys, proxy and running resources, and you can go back to Coolify 4.5.3 the same way. The full procedure, including the dry-run check and the way back: [docs/MIGRATING.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/MIGRATING.md).

Other Coolify versions: upgrade Coolify to 4.5.3 first. Coolify 4.6 and later are not supported yet.

## What's in it

- The Coolify REST API (`/api/v1`) with upstream's responses and errors, and the web UI, ported page for page.
- Deployments for every build pack (Dockerfile, Docker Compose, Docker image, static, Nixpacks, Railpack), preview deployments, rollbacks, build servers, registries and Swarm.
- Servers over SSH with pinned host keys, Traefik and Caddy proxies, Sentinel metrics, the terminal, server transfers and Docker cleanup.
- Standalone databases with S3 backups and imports, and one-click services from Coolify's template catalogue.
- The scheduler, Git sources, secret managers, managed DNS and Cloudflare Tunnels, notifications and GitHub runners.
- Everything Coolify changed up to 4.5.3, including:
  - S3 virtual-hosted-style URLs, S3v4-signed backups with retried uploads, and S3 keys that never appear on a command line.
  - Axiom edge domains and Fluent Bit 5.1 for log drains.
  - Preview deployments that keep production values.
  - Application commands and database configuration limited to admins and `read:sensitive` tokens.
  - Cloning with volume data while the source is stopped.
  - Automatic validation of new cloud servers, and clearer Hetzner, DigitalOcean, Vultr and Cloudflare errors.
  - Developer-view flag directives for environment variables.
  - Retried connection failures for idempotent HTTP calls.
- **Plugins (preview).** WebAssembly plugins in a capability-checked sandbox, with signed registry support and panels in the dashboard. Four first-party plugins (alerts, Healthchecks.io, deploy chains and delivery metrics) live in the repository. The public plugin catalogue is not published yet, so for now plugins can only be installed in development mode. See [docs/PLUGINS.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/PLUGINS.md).

## Performance

On 2 CPU cores, against Coolify with the same data: 30 MiB of memory at idle instead of 372 MiB, 0.5 ms of CPU per API request instead of 11–12 ms, and 6–9× more API requests per second. The setup and every number: [compat/bench/RESULTS.md](https://github.com/coolify-rs/coolify-rs/blob/main/compat/bench/RESULTS.md).

## Known differences

Read [docs/KNOWN_LIMITATIONS.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/KNOWN_LIMITATIONS.md) before you switch. Notable ones: sessions are held in memory, so restarts and upgrades sign everyone out; background work runs in the coolify-rs process rather than a Redis queue, so a restart drops running deployments.
