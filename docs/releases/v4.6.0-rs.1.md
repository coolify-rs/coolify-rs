coolify-rs 4.6.0-rs.1 matches **Coolify 4.6.0**, the current Coolify release. If your Coolify updates itself, this is the release that can take it over.

coolify-rs is an independent reimplementation of Coolify in one Rust service. It is not affiliated with or endorsed by coolLabs.

## Install

On a clean server, as root:

```bash
curl -fsSL https://github.com/coolify-rs/coolify-rs/releases/latest/download/install.sh | sudo bash
```

Requirements, settings and upgrades: [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md).

## Migrate from Coolify 4.6.0

Back up, run the dry-run check, then run the same installer on your Coolify server. It keeps your database, secrets, SSH keys, proxy and running resources, and you can go back to Coolify 4.6.0 the same way: [docs/MIGRATING.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/MIGRATING.md).

On Coolify 4.5.3 or older: upgrade Coolify to 4.6.0 first, then migrate.

## Upgrade from 4.5.3-rs.1

Use the Upgrade button, or `upgrade.sh` as in [docs/INSTALL.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/INSTALL.md#upgrade). On its first start, 4.6.0-rs.1 applies Coolify 4.6.0's 15 schema changes to your database, as Coolify's own upgrade would.

## What's new

Everything Coolify changed from 4.5.3 to 4.6.0, including:

- **Scoped access.** Team members and API tokens can be limited to some projects and environments, at read, write, deploy or delete level. Deleting is its own ability; a token never holds more access than its member; invitations can carry access.
- **API tokens.** Edit a token's access, pause and resume it, roll its secret, and get a warning 7 days before it expires.
- **Git HTTPS credentials** for private repositories on any Git host.
- **New API endpoints** for DNS records, integration tokens and resource secret managers.
- **Update channels** (stable, preview, nightly, or a custom image tag) in Settings → Update.
- **Tables** sort by clicking a column header and filter by clicking a value; row actions are in one menu.
- **Fixes:** backups to S3 from IPv6-only servers, build secrets kept out of the running container, init script file names can no longer escape their folder, cancelling a deployment stops its build-server helper, unreachable servers no longer slow the dashboard, and more.
- **Hi.Events** in the service catalogue.

Also new in coolify-rs:

- **Laravel applications built with Nixpacks** now deploy, as in Coolify.
- **Long-lived Coolify installations** carry names of migrations that Coolify later renamed or removed. coolify-rs now recognises them; 4.5.3-rs.1 started read-only on such a database.

## Known differences

Read [docs/KNOWN_LIMITATIONS.md](https://github.com/coolify-rs/coolify-rs/blob/main/docs/KNOWN_LIMITATIONS.md) before you switch. Notable ones: coolify-rs has no MCP server; sessions are held in memory, so restarts and upgrades sign everyone out; background work runs in the coolify-rs process, so a restart drops running deployments.
