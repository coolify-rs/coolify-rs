# ADR 0004: Adopt the upstream database schema in place

Status: accepted (2026-10-27)

## Decision

coolify-rs reads and writes the upstream PostgreSQL schema exactly as upstream does and never runs upstream DDL.
A startup schema guard compares the `migrations` table with `compat/baseline/supported-migrations.txt` (generated by
the engine) and switches to read-only when the database has migrations this build was not validated against.
Rows are rendered with `row_to_json` (column order, native types) and per-model specs reproducing `$hidden`,
datetime casts and controller-level `makeHidden`; unknown columns are dropped until reviewed.

## Alternatives rejected

- Separate Rust schema + import: duplicates data, breaks side-by-side operation, adds a lossy migration step.
- Compile-time-checked queries (`sqlx::query!`): require a live DB at build time and cannot express "optional column".

## Consequences

Release-to-release schema drift is handled explicitly (engine → plan → baseline update), not silently.
Writes must reproduce model side effects (e.g. `Project::created` inserts settings and a `production` environment);
these are listed in the repository modules and verified by differential cross-reads.
